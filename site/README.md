# HoloGPU / Temples product site

A product page with a top-left view selector for HoloGPU, Light Temple, Water Temple, and Fire Temple. Each view has its own copy, accent colors, featured experiments, and interactive WebGPU sculpture. The URL stores the selected view in `?site=`. Browser back/forward works. The entire temple card is a native link, supporting image/text clicks, keyboard navigation, and opening in a new tab. Every site exposes its complete experiment catalogue in the product page (HoloGPU, Light Temple, Water Temple, Fire Temple and Eightfold Path; the counts come from `src/catalogues.json`). The gallery renders 12 cards initially, then adds batches automatically as its scroll sentinel approaches the viewport. A Load more button provides a keyboard fallback. Search checks the complete catalogue before batching; changing sites clears the filter. Preview images receive a source only while intersecting the viewport, are decoded asynchronously, and drop their source when off screen. Opening a lab or hiding the tab suspends background previews. The hero initializes when visible and pauses GPU rendering when off screen or behind a demo.

The lab dialog loads the real project builds hosted at `/labs/hologpu/`, `/labs/lighttemple/`, `/labs/watertemple/`, and `/labs/firetemple/`. Featured experiments link directly to their original routes. Closing the dialog unloads its GPU resources. Full-screen links also work independently.

## Development

Run `npm install`, then `npm run dev` (the Astro dev server on port 5188). Run `npm run build` to generate the static site into `dist/`. Requires Node 22.12 or later (declared in `engines`).

The site is generated by Astro (story 5.1). The landing page is `src/pages/index.astro`; its behaviour lives in `src/main.js` and `src/gallery.js`, imported as a client script. Effect pages are generated from the catalogue at `src/pages/effects/[project]/[id].astro`, and guides are Markdown pages under `src/pages/guides/` sharing the shell in `src/layouts/Doc.astro`.

## Deploy

GitHub Actions (`.github/workflows/pages.yml`) builds and publishes to GitHub Pages at https://s4njee.github.io/holofx/ on every push to `main`. The repo is served under `/holofx/`, so the build runs with `SITE_BASE=/holofx/`: `scripts/build-labs.mjs` builds each lab under the same prefix and an Astro build hook prefixes the site's root-absolute paths. Build the same way locally with `SITE_BASE=/holofx/ npm run build` at the superproject root.

The same build is also served at https://mk7s.dev/holofx/ (the Cloudflare Pages project `mk7s`, in `../../mk7s`). `npm run publish:mk7s` at the superproject root builds it and copies `site/dist` into mk7s's `public/holofx/`; add `-- --deploy` to build mk7s and deploy it with Wrangler, or `-- --skip-build` to reuse a `site/dist` already built with `SITE_BASE=/holofx/`.

The product page imports the HoloGPU runtime from the `hologpu` submodule through the `@mk7s/hologpu-core` alias (`../hologpu/packages/core/src`). It reads effect metadata and posters directly from the submodules: `hologpu/packages/effects/src`, `firetemple/src/effects`, `watertemple/src/effects`, and `lighttemple/src/gallery/registry.ts`.

The lab bundles are built into the git-ignored `public/labs/` from the submodules by the superproject's `scripts/build-labs.mjs`, each with `--base /labs/<project>/`. Refresh them with that script, then rebuild this site.

The metadata snapshot is `src/catalogues.json`. Refresh it with `npm run catalogue` (runs `scripts/import-catalogues.mjs`), which reads the submodule registries and copies available posters into `public/images/catalogues/`.

Card images are captured animated AVIFs of the real demos; an experiment whose capture is missing or failed falls back to its project's poster, a local screenshot or text. `npm run site:update` (below) captures every experiment that has no animated preview yet. Animated previews loop at 8 fps with 20 frames at 480×300; their JPEG first frames are used for reduced motion or an AVIF decoding failure. The same viewport observer controls both animated and still preview sources. Reduced-motion changes apply to already visible cards. The product hero is a custom WGSL sculpture running on the HoloGPU runtime; it is an illustrative showcase, not a measurement of temple effects. A static preview is used when WebGPU is unavailable. The page follows the reduced-motion preference and offers a pause control. Lab performance and browser coverage remain those documented by each original project.

## Validation

Verified in Chromium with WebGPU: all four views and lab galleries, featured-effect links, URL/history behavior, pause/resume, source links, dialog dismissal, a 390 px mobile viewport without horizontal overflow, reduced motion, and forced static fallback. Also verified full-card temple navigation, all four default catalogue counts, search/empty/reset states, and a one-to-one match between listed experiment ids and their bundled lab registries. Infinite-scroll checks verify the initial 12-card batch, no off-screen catalogue image requests, viewport-only active image sources, automatic access to every experiment in all four catalogues, full-catalogue search, empty/reset states, and preview suspension while a demo is open.

The hosting identity is persisted in `.openai/hosting.json`. Publish through the Sites source workflow and deployment operation appropriate to the existing audience; do not create a second project.

## Regenerating the site

`npm run site:update` at the superproject root (`scripts/update-site.mjs`) rebuilds everything from the submodules' current checkouts, in order: the libraries, every project's lab, each project's `catalogue.json` and this site's snapshot of them (`src/catalogues.json`), and the Astro build. It then serves that build itself (a small static server on port 5188, or a free port if that is taken; `astro preview` is a per-project singleton that may be serving another build), captures an animated preview for every experiment that doesn't have one, folds the new previews into the snapshot, rebuilds the site and verifies every clip. Pass `--base /holofx/` for the GitHub Pages / mk7s.dev sub-path, and `--publish` (or `--deploy`) to stage the result into `../../mk7s` (see Deploy). `--skip-libs`, `--skip-labs` and `--skip-capture` reuse what is already built; `--only` and `--recapture` take projects or `project/id` keys; `npm run previews` only captures, against the existing `dist/`. A capture that fails leaves the card on its poster and makes the command exit non-zero, after the site is rebuilt.

## Animated preview capture

`scripts/capture-animated-previews.cjs` does the capturing (run it through `site:update` or `npm run previews`, which serve the build for it). It opens each experiment's real lab route (`/labs/<project>/?effect=<id>`, or `#/x/<id>` for Light Temple) in headless Chromium with hardware WebGPU (`--use-angle=metal`), pins the canvas to 480×300, drags the pointer in one slow circle, and screenshots 20 frames at 8 fps; `avifenc` encodes them into a looping AVIF and `ffmpeg` writes the first frame as the reduced-motion JPEG. A clip with no visible motion is rejected. Raw frames stay under ignored `.site-runtime/capture/`, and a rerun reuses them. Some static diagnostics are recorded while their controls are scrubbed. `--text-only` keeps the original scope (cards with no image at all).

`src/animated-previews.json` records every clip's source route, capture settings, frame count, still frame and size; `src/animated-preview-targets.json` records the original 100-card scope. `node scripts/verify-animated-previews.cjs` decodes every clip, confirms dimensions, frame count, infinite looping and motion, and expects one for every catalogue experiment (`--partial` checks only those that exist). `node scripts/apply-animated-previews.mjs` applies the manifest to the snapshot; `npm run catalogue` does the same. Catalogue refreshes preserve captured assets.
